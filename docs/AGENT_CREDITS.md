# Termeow agent credits — MVP

One credit is $0.01 of retail value. A first-time Privy user receives 500 credits ($5 retail value) once, keyed by their Privy user ID in Neon. Voice is posted at 40 credits ($0.40) per minute. At settlement, the debit is the greater of duration-based pricing and **twice the actual `metadata.cost_fiat`** reported by ElevenLabs. That maintains at least 50% gross margin on the ElevenLabs cost; it does **not** account for other tool/API, payment, RPC, or infrastructure costs. Review actual margins weekly and raise the posted floor if ancillary cost warrants it.

The private ElevenLabs agent currently caps conversations at 600 seconds. Before issuing a token, the backend verifies that cap and reserves 400 credits (the maximum duration charge) atomically in Neon. The session's ElevenLabs conversation ID is stored server-side. A browser disconnect asks for reconciliation, and a server sweeper retries pending sessions every minute. On `done` or `failed`, the backend reads provider-reported duration and USD cost, records the charge, and refunds unused credits. Any provider cost above the hold becomes account debt; subsequent top-ups pay that debt first. A never-used token is refunded only after expiry, the maximum call window, and multiple provider 404s. The UI may temporarily show less *available* credit while a call is active. The hold means a user with fewer than 400 credits cannot start a new call, even if they could afford a shorter one; a future per-call duration override could improve this without weakening the cap.

Top-ups are $5–$500. The app supports SOL or native USDC on Solana, and ETH or canonical USDG on Robinhood Chain (chain ID 4663). A short-lived quote uses a fresh CoinGecko USD price; stablecoins below $0.98 are rejected. Privy prompts the connected wallet to sign a **direct transfer** to the configured treasury address. The backend independently checks that the sender is linked to the authenticated Privy user, then verifies the finalized Solana instruction or a successful, confirmed Robinhood receipt and USDG `Transfer` log. Recipient, token/mint, sender, amount, quote time, and unique transaction hash must match before Neon credits the account in one database transaction. Signing, gas, and blockchain payments remain user-authorized; the server never holds wallet keys. Do not treat a submitted transaction as credited until verification succeeds.

Storage: `termeow.agent_credit_accounts` holds spendable balance/debt; `termeow.agent_credit_ledger` is an append-only audit trail; `termeow.agent_credit_quotes` binds payment intents and unique transaction hashes; `termeow.agent_voice_sessions` stores holds and provider settlement. Apply `npm run db:migrate` to the intended Neon database before enabling this code. No financial state is kept in browser storage; only a pending quote/transaction ID is saved locally to let the user retry verification after a page reload.

Operational safeguards: keep the ElevenLabs agent private so its public agent ID cannot bypass `/api/agent/session`; do not re-enable the former `VITE_ELEVENLABS_AGENT_ID` fallback. Alert on pending sessions older than 20 minutes, 404 refunds, debt, provider cost over $0.20/minute, quote/settlement failures, and depeg. Verify all four payment flows with small transactions on the intended production chains before inviting paid users. Native-token prices depend on CoinGecko availability and top-ups fail closed when pricing is unavailable.
